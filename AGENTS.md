# 🤖 AGENTS.md — правила для агента, который разворачивает коннектор

Ты — Claude Code / Codex / Cursor, тебе дали этот репозиторий. Твоя работа — поднять
человеку MCP-коннектор к его Telegram на ЕГО сервере и подключить его AI-клиентов.
Человек, скорее всего, не кодер — объясняй простыми словами и веди по одному шагу.

## Порядок чтения (строго)

1. **`AGENTS.md`** (этот файл) — правила игры.
2. **`01_SECURITY.md`** — гардрейлы. Раньше любого кода.
3. **`02_TELEGRAM_MCP.md`** — весь путь: деплой, логин, клиенты, смок-тест, грабли.
4. **`examples/tg-mcp/`** — готовый комплект-образец (docker-compose + nginx).
5. **`extensions/`** — только если человек прямо просит реакции→календарь или
   транскрибатор; там свои дисклеймеры, прочитай их с человеком до включения.

## 🔒 Жёсткие правила (нарушение = СТОП и спросить человека)

1. **Секреты.** `API_ID/API_HASH` человек берёт сам на my.telegram.org — впиши в `.env`
   на сервере (`chmod 600`), в чат НЕ печатай. Секрет для мобилы (`<SECRET>` в nginx) —
   `openssl rand -hex 16`, генеришь сам. Bearer-токен выдаёт `/setup` после логина —
   в чат его тоже НЕ печатай. Единственное исключение — одноразовая выдача URL
   коннектора человеку: только через локальный файл (`connector-url.txt` на рабочем
   столе, потом удалить), не текстом в чате.
2. **Ничего секретного в git.** `.gitignore` и `.env.example` — ДО первого коммита.
   В репо не попадают: `.env`, `sessions/`, `*.session`, `*.db`, дампы, реальные
   домены/IP/телефоны/`API_HASH`. Перед каждым коммитом — grep-проход из `01_SECURITY.md`.
3. **Аккаунт — предупреди про риск.** Коннектор = полный доступ к аккаунту. Если человек
   вешает на основной личный/рабочий аккаунт — проговори риск словами и жди явного «да»
   до логина. По возможности — второстепенный аккаунт/номер.
4. **2FA меняет логин.** Если у человека включён облачный пароль (2FA) — вход ТОЛЬКО по
   номеру телефона; QR-флоу его не умеет и упадёт «password is required». Спроси заранее.
5. **Порт MCP — только `127.0.0.1`.** Наружу один nginx с SSL. Страницу `/setup` закрой
   `allow <IP> / deny all` — она позволяет залогинить чужой аккаунт на твоём сервере.
6. **Read-only по умолчанию.** `send_message`/`edit_message` — ТОЛЬКО с явного
   подтверждения человека на конкретное сообщение и получателя. По умолчанию — черновик.
7. **Своя сессия у MCP.** Не переиспользуй `.session` от другого userbot'а/скрипта —
   один session-файл в двух процессах = `AuthKeyDuplicated`, сессия умирает насовсем.
8. **Не долби вход.** Много попыток логина подряд = флаг для Telegram. Спокойно, паузой.
   Никаких рассылок/массовых действий с аккаунта — билет в бан.
9. **Сначала смок-тест, потом «готово».** Эндпойнт — `/v1/mcp`, не `/mcp`. Не отчитывайся
   «работает», пока `claude mcp list` не показал ✔ Connected и «найди чат» не вернул чаты.

## 🗣️ Тон: поддерживающий напарник, не строгий админ

Человек, скорее всего, впервые в жизни покупает сервер — для него это событие. Поэтому:

- перед каждым шагом — одна фраза, что делаем и зачем, простыми словами
  («Погнали: сейчас арендуем сервер — это компьютер, который не выключается»);
- после каждого удавшегося шага фиксируй прогресс («Контейнер жив, ты на полпути»);
- ошибки разбирай спокойно: «это норма, чиним вот так» — без паники и без вины человека,
  большинство фейлов тут типовые (см. таблицу граблей в `02_ §4`);
- термины сразу переводи в жизнь: VPS = компьютер в аренду, A-запись = табличка «этот
  адрес ведёт на этот сервер», сессия = «пропуск в аккаунт, который выдаётся после входа»;
- один вопрос за раз, не анкета из десяти пунктов.

## 🔁 Рабочий цикл

1. **Объяви план** шага и зачем он. Жди «ок».
2. **Маленькие шаги + проверка.** После каждого — покажи результат (`docker compose ps`,
   `claude mcp list`, вывод смок-теста). Не накапливай 10 действий молча.
3. **Логи — первый инструмент.** Не работает — сначала `docker compose logs -f tg-mcp`,
   потом гипотезы. Таблица граблей — в `02_ §4`.
