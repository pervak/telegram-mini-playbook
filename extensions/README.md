# extensions/ — экспериментальные расширения (по желанию, со своими рисками)

Базовый плейбук (`README` → `01_SECURITY` → `02_TELEGRAM_MCP`) даёт **read-first коннектор**:
читать, искать, слать с подтверждения. Этого достаточно 90% людей — **если тебе хватает,
сюда можно не ходить.**

Здесь — два **дополнения** поверх готового коннектора. Оба выходят за рамки «руки в чате»
и несут отдельные риски, поэтому вынесены в `extensions/`, а не в основной путь.

| Расширение | Что делает | Главный риск |
|---|---|---|
| [`01_REACTIONS_CALENDAR.md`](01_REACTIONS_CALENDAR.md) | ставишь реакцию на сообщение → агент заводит событие в Google Calendar | нужен фоновый режим или регулярный опрос → ближе к «userbot-автоматизации» (серая зона ToS) |
| [`02_GROQ_TRANSCRIBER.md`](02_GROQ_TRANSCRIBER.md) | голосовое из Telegram → текст через Groq Whisper | голосовое (часто чужое) уезжает в сторонний сервис (Groq) |

## ⚠️ Прочитай, прежде чем включать хоть одно

1. **Это НЕ «поставил и работает».** Оба — рецепты (архитектура + код-скелет + грабли),
   которые агент собирает С ТОБОЙ под твой сервер. Не законченные продукты.
2. **Свои дисклеймеры в каждом файле** — про ToS, приватность, данные третьих лиц.
   Агент обязан прочитать их с тобой ДО включения и получить явное «да».
3. **Правила `01_SECURITY.md` действуют полностью.** Секреты в `.env`, отправка/запись —
   с подтверждения, отдельный аккаунт по возможности.
4. **Данные третьих лиц.** Реакция на чужое сообщение и транскрипт чужого голосового —
   это обработка чужих данных. Заводишь себе в календарь/текст для себя — ок; публиковать,
   пересылать, скармливать это куда-то ещё — твоя ответственность (см. `01_ §9`).
5. **Начни с малого.** У обоих есть **низкорисковый режим по запросу** (агент делает разово,
   когда ты попросил) против **фонового 24/7** (выше риск бана и утечки). По умолчанию —
   по запросу. Фон — осознанно и позже.

Не уверен, нужно ли тебе это, — значит не нужно. Возвращайся, когда базовый коннектор
станет тесен.
