# Расширение · Реакция → событие в календаре

**Идея:** ставишь на сообщение оговорённую реакцию (например 📅) — агент понимает «это
про встречу», вытаскивает дату/время из текста и заводит событие в Google Calendar. Ставишь
реакцию — событие появилось.

> Это **рецепт**, а не готовый продукт: архитектура + скелет + грабли. Агент собирает его
> с тобой поверх уже поднятого коннектора из `02_TELEGRAM_MCP.md`.

---

## ⚠️ Дисклеймеры — прочитать до включения

1. **ToS.** Разовый разбор по твоему запросу («глянь реакции за сегодня») — это обычное
   чтение, ничем не отличается от базового коннектора. А вот **фоновый watcher 24/7**,
   который сам крутится и слушает события, — это уже userbot-автоматизация, **серая зона по
   ToS Telegram**. Риск блокировки небольшой, но не нулевой; на рабочий аккаунт — не вешай.
2. **Данные третьих лиц.** Сообщение, на которое ты реагируешь, часто писал не ты. Его текст
   уедет в твой Google Calendar (сервер Google). Заводишь себе напоминание — ок; помни, что
   это обработка чужих данных, не пересылай их дальше.
3. **Google-доступ.** Нужен OAuth к Calendar API. Токен Google = доступ к твоему календарю:
   `chmod 600`, в `.gitignore`, не в чат (правила `01_SECURITY.md` целиком).
4. **Ложные события.** Дату из живого текста агент угадывает и **иногда ошибается**
   («завтра», «в четверг», «после праздников»). Держи режим «покажи, что понял → подтверди
   → создавай», не «молча создал».

---

## Два режима (по возрастанию риска)

| | **A. По запросу** (дефолт, низкий риск) | **B. Фоновый watcher** (осознанно, выше риск) |
|---|---|---|
| Как | ты пишешь агенту «разбери мои 📅-реакции за сегодня» | демон каждые N минут опрашивает реакции |
| ToS | обычное чтение, как базовый коннектор | userbot-автоматизация, серая зона |
| Когда | почти всем; начни отсюда | когда режим A стал тесен и ты принял риск |

**Начинай с A.** B — только после того, как A работает и ты сознательно взял на себя риск фона.

## Архитектура

```
Telegram (ты ставишь реакцию 📅)
        │  MTProto: messages.getMessagesReactions / messages.getRecentReactions
        ▼
fast-mcp-telegram  →  invoke_mtproto  →  агент читает реакции и текст сообщения
        │
        ▼  агент парсит дату/время (и ПОКАЗЫВАЕТ тебе, что понял)
Google Calendar API  events.insert   →   событие в календаре
```

Ничего нового в контейнер ставить не надо: реакции достаются штатным `invoke_mtproto`.
Разбор даты и вызов Google — на стороне агента/скрипта.

## Скелет (режим A, «по запросу»)

Реакции достаются сырым MTProto (аргументы — строго `method_full_name` + `params_json`
как **JSON-строка**, см. `02_ §2`). Дальше агент разбирает текст и создаёт событие:

```python
# ponytail: скелет режима A. Дату НЕ парсим регэкспом — отдаём агенту, он надёжнее
# на "завтра"/"в четверг" и ПОКАЗЫВАЕТ результат на подтверждение до events.insert.
from googleapiclient.discovery import build
from google.oauth2.credentials import Credentials

def make_event(summary, start_iso, end_iso, tz="Europe/Moscow"):
    creds = Credentials.from_authorized_user_file("google_token.json",
              ["https://www.googleapis.com/auth/calendar.events"])  # chmod 600, в .gitignore
    cal = build("calendar", "v3", credentials=creds)
    ev = {"summary": summary,
          "start": {"dateTime": start_iso, "timeZone": tz},
          "end":   {"dateTime": end_iso,   "timeZone": tz}}
    return cal.events().insert(calendarId="primary", body=ev).execute()["htmlLink"]

# self-check: событие валидно только если конец позже начала
def _check():
    from datetime import datetime
    s, e = "2026-07-22T15:00:00", "2026-07-22T16:00:00"
    assert datetime.fromisoformat(e) > datetime.fromisoformat(s)
    assert "T" in s and "T" in e   # ISO-8601, иначе Google 400
if __name__ == "__main__":
    _check(); print("ok")
```

Промпт агенту (режим A):
> «Прочитай через telegram-MCP сообщения, где я поставил реакцию 📅, за сегодня. Для каждого
> вытащи суть встречи и дату/время. **Покажи мне списком, что понял, и жди “ок”.** После
> подтверждения — заведи события в Google Calendar. Сомневаешься в дате — спрашивай, не выдумывай.»

## Google Calendar — доступ (один раз)

1. [console.cloud.google.com](https://console.cloud.google.com) → новый проект → включи
   **Google Calendar API**.
2. OAuth consent screen (External, Testing — добавь свой email в тестеры) → Credentials →
   **OAuth client ID → Desktop app** → скачай `credentials.json`.
3. Первый запуск локально открывает браузер, сохрани `google_token.json` (`chmod 600`, в `.gitignore`).
4. Scope минимальный — `calendar.events` (создавать события), не полный `calendar`.

## Режим B (фон) — если сознательно берёшь риск

Демон каждые N минут: `invoke_mtproto` по реакциям → дельта с прошлым проходом → на новые
📅 создаёт события. Держи **дедуп** (запоминай обработанные `message_id`, иначе дубли каждый
проход) и **паузу** между опросами (частый поллинг = FloodWait и флаг Telegram). Systemd с
`Restart=always`. Это уже фоновый userbot — перечитай дисклеймер №1.

## Грабли

| Симптом | Причина | Фикс |
|---|---|---|
| Google `400 invalid time` | дата не ISO-8601 или конец ≤ начала | нормализуй в `YYYY-MM-DDTHH:MM:SS`, конец > начала |
| Дубли событий в фоне | нет дедупа обработанных сообщений | храни `message_id` обработанных |
| `FloodWait` | частый поллинг реакций | увеличь интервал, читай порциями |
| Google `403 access_denied` | email не в тестерах OAuth-экрана | добавь себя в Testing users |
| Не тот часовой пояс | не задан `timeZone` | ставь явный TZ (`Europe/Moscow`) |
